# 车牌识别三模式与原图 ROI 实验

## 目的

本轮不是替换正式车牌模型，而是在同一 Qt 工程、同一套输入和显示链路中比较三种车牌识别方案，验证“检测使用缩小画面、OCR 回到原始画面裁剪”是否带来可重复的字符识别收益。

## 三种模式

| Qt 模式 | 检测/识别模型 | OCR ROI 来源 | 用途 |
|---|---|---|---|
| 标准模式 | legacy | 640×360 检测链路 | 当前正式基线，默认启动 |
| 规则模式 | v291_candidate | 640×360 检测链路 | 验证候选模型与规则分类 |
| 原图ROI实验 | v291_candidate | 当前所选原始画面区域 | 只验证高分辨率裁剪对现有 94×24 OCR 的收益 |

“逐帧结果（测试）/稳定显示（默认）”在实验阶段保留。逐帧结果用于排除轨迹、缓存、EMA 和投票对结果的影响；稳定显示用于观察最终交互效果。正式版本是否隐藏该开关，应在实验结论明确后再决定。

## 数据链路

原图 ROI 实验仍使用 640×360 图像完成车牌检测。检测得到并经过现有透视点排序、可靠性判断和横向补偿的四点坐标后，程序把四点映射回所选原始画面区域，仅复制该区域，再在局部范围完成 RGB565 到 BGR 转换和透视变换，最终仍缩放为现有 `plate_reco.rknn` 要求的 94×24。

因此，该模式可以验证更好的采样源是否有收益，但不会突破 94×24 OCR 模型本身的输入上限。若收益很小，不能据此认定高分辨率 OCR 无价值；它只能说明“原图重采样 + 现有 OCR 模型”的收益有限。

总览画面需要复制 1920×1080 RGB565，约 4.15 MB/送检帧；单通道画面只复制 640×360，约 0.46 MB/送检帧。测试时必须同时记录 CPU、内存带宽、NPU FPS 和端到端耗时。

## 构建与部署

在 Ubuntu 虚拟机工程根目录执行：

```bash
./tools/build_arm64.sh
./tools/deploy_test.sh
```

部署脚本会创建新的版本化测试目录，不覆盖板端正式目录。板端当前测试目录可通过以下命令确认：

```bash
TEST_ROOT="$(cat /userdata/Apps/RK3568_PTZ_Qt_test_current.path)"
echo "$TEST_ROOT"
cd "$TEST_ROOT/scripts"
./start.sh
```

默认从“标准模式 + 稳定显示”启动。也可以只为一次启动覆盖配置：

```bash
NPU_MODEL_PROFILE=v291_candidate \
PLATE_CROP_SOURCE=original \
PLATE_POSTPROCESS_MODE=raw \
./start.sh
```

启动后仍可在 Qt 页面中切换三种模式；运行时切换不需要重启程序。

## 推荐 A/B 测试顺序

1. 固定同一输入源、同一批图片、同一显示通道、同一置信度和 NMS。
2. 先选择“规则模式 + 逐帧结果”，每组至少运行 60 秒并记录识别结果、FPS 和耗时。
3. 只切换到“原图ROI实验 + 逐帧结果”，重复相同图片顺序。
4. 分别在总览画面与单通道画面重复，避免把源 ROI 大小的差异误认为模型收益。
5. 最后切换为稳定显示，观察框切换、文字跳变和实际 UI 体验。
6. 标准模式单独作为正式基线，不要把 legacy 与 v291 的模型差异归因于原图 ROI。

至少覆盖：小车牌、大车牌、明显倾斜、运动模糊、暗光绿色牌、强反光、复杂背景、港澳牌及无车牌负样本。逐图记录完整正确、字符错误、漏检、误检和颜色/类型错误。

## 日志确认

```bash
TEST_ROOT="$(cat /userdata/Apps/RK3568_PTZ_Qt_test_current.path)"
LOG="$TEST_ROOT/logs/rk_dual_screen_video.log"

grep -E '\[NPU\] plate config active:|\[NPU\] original ROI' "$LOG" | tail -n 100
```

原图模式应出现 `crop_source=original`。周期日志中的 `actual=original` 且 `crops` 大于 0，才表示 OCR 实际使用了原图裁剪；若 `fallback` 大于 0，应同时检查 `reason`。界面也会显示请求/实际 ROI 来源及回退计数。

## 判定建议

只有在相同输入的逐帧对比中，完整字符正确率有稳定提升，同时端到端 FPS、CPU 使用率和交互延迟仍在目标范围内，才建议保留该链路。否则继续使用标准模式，并把样本与失败类型交给 OCR 模型训练成员决定是否训练更大输入的识别模型。

本实验不会修改或覆盖任何 `.rknn` 文件，也不会改变板端正式目录。
