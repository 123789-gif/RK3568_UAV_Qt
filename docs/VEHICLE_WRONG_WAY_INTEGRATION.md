# 车辆逆行检测集成说明

## 运行边界

- 逆行检测作为 `NpuTaskType::VehicleWrongWay` 接入现有单任务 `NpuInferenceWorker`。
- 与车牌识别、行人检测、闯红灯检测互斥，不启动独立后台进程。
- 只允许在 CH1～CH9 单路选路下启动；九宫格总览分辨率不足，界面会拒绝启动。
- 每个 CH 使用独立的 `config/vehicle_wrong_way_chN.ini`，坐标归一化到 `[0,1]`。
- 视频源、配置 revision 或任务切换时清空跟踪器，防止旧轨迹串入新场景。

## 模型契约

- 文件：`models/yolov8_car_640x320_mmse.rknn`
- SHA256：`7f88ec93cadaacac7233adc4d6dbc07d2bcd4937b75d445da062001e79367a94`
- 输入：`1x3x320x640`
- padding：114
- 输出：`1x68x4200`
- 类别：`car / bus / van / truck`

车辆任务复用已经板端使用的 640x320 YOLO 解码实现，但不修改旧行人/车牌的
768x448、padding 255 默认契约。

## 数据流

```text
PCIe当前单路CH RGB565 640x360
  -> 640x320/pad114车辆预处理
  -> RKNN车辆检测
  -> 原640x360坐标框
  -> CPU车道归属/轻量跟踪/时间窗方向估计
  -> NpuFrameResult::vehicles + WrongWay事件
  -> DSI预览/状态 + HDMI OSD
```

方向判定使用车辆框底边中心。时序参数全部使用毫秒，不直接使用显示帧号，避免
显示60 fps和NPU目标15 fps之间的采样差异改变规则语义。中性或停车证据会清空
进入/解除连续计时，不允许非连续反向证据累计触发。

## 首轮上板验收

1. `scripts/check_runtime.sh` 检查车辆模型、四类映射和整体 SHA256。
2. 分别回归 legacy/v291 车牌、行人和闯红灯任务，确认模型切换和输入规格未回归。
3. 在视频显示页选择单路 CH，进入“逆行检测”页配置每条车道四点区域和正常方向。
4. 正常行驶、停车、逆行、短时遮挡、双向多车道分别测试。
5. 切换 CH、重画 ROI、改变稳定策略后确认轨迹 ID 从 1 重新开始。
6. 记录平均/P95/最大推理耗时、实际 NPU FPS、NPU 占用和温度。

三个稳定策略仅是初始参数，最终应根据真实相机视角标定。固定相机移动或PTZ动作
会破坏图像坐标方向假设，发生相机运动时必须停止或重置逆行检测。
