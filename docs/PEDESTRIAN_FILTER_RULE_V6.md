# 全画面可信行人与违法判定 v6 验收

## 已确认的数据流

违法规则开启时使用以下唯一正式链路：

```text
总览1080P
  -> 640x360 RKNN行人检测
  -> 全画面几何过滤
  -> 新轨迹/已跟踪轨迹置信度迟滞
  -> 连续命中确认
  -> 可信行人框
  -> 平滑框底边中点
  -> 斑马线空间迟滞
  -> 稳定交通灯投票
  -> 合法/违法时间状态机
  -> Qt与HDMI正式OSD
```

只开启行人模型、不启用违法规则时，继续显示模型原始框，用于独立验证RKNN模型效果。启用违法规则后，被几何、置信度或时序确认拒绝的框不进入Qt预览、HDMI OSD和规则状态机。

## 默认过滤参数

参数保存在 `config/pedestrian_violation.ini` 的 `[filter]` 节，不增加页面按钮：

- 最小框高：24 px（640x360坐标）
- 高宽比 `h/w`：1.80～5.00
- 新轨迹置信度：0.60
- 已跟踪轨迹最低置信度：0.45
- 连续确认：3次命中
- 最大确认间隔：350 ms
- 轨迹TTL：1000 ms
- 框EMA：0.50

这些参数用于压低演示误报，不替代模型精度。如果高置信度、尺寸合理的固定物体仍被持续识别为人，需要补负样本微调模型。

## 业务真值表

| 稳定灯态 | 底框中点在斑马线内 | 结果 |
|---|---:|---|
| 绿灯 | 是 | 合法 |
| 绿灯 | 否 | 违法：未走斑马线 |
| 红灯 | 是 | 违法：红灯通行 |
| 红灯 | 否 | 违法：红灯且未走斑马线 |
| 未知 | 任意 | 状态未知，不产生事件 |

已知违法状态持续600 ms后生成事件。同一连续违法过程只生成一次事件；稳定恢复合法后才解除事件锁存。斑马线边界使用默认5 px迟滞，避免检测框抖动导致状态来回切换。

## 显示与诊断

- `LEGAL`：绿色
- `WAIT`：黄色，违法条件累计中
- `RED`、`OUTSIDE`、`RED+OUT`：红色违法原因
- `UNKNOWN`：灰色，灯态未知或区域未配置

行人页显示原始框数、可信框数、几何拒绝数、置信度拒绝数和待确认数。运行日志每约5秒输出一条 `[NPU] pedestrian filter` 统计。

## 上板测试

1. 只开启行人模型，确认原始模型框仍可见。
2. 开启违法规则，前两次孤立检测不应进入正式OSD；稳定行人在约3次命中后出现。
3. 使用静态非行人目标测试30秒，记录 `reject_geometry`、`reject_confidence` 和是否形成可信轨迹。
4. 强制绿灯：斑马线内为 `LEGAL`，斑马线外应先 `WAIT`，约600 ms后为 `OUTSIDE`。
5. 强制红灯：斑马线内约600 ms后为 `RED`，斑马线外为 `RED+OUT`。
6. 自动灯态下遮挡交通灯，状态应为 `UNKNOWN`，不得新增违法事件。
7. 让底框中点在斑马线边界附近移动，确认5 px迟滞带内不反复切换。
8. 绿灯进入斑马线后切为红灯，保持在斑马线上约600 ms后必须转为 `RED`。
